# HIT-Website-Project

Instructions for coding agents working in this repository. (Claude Code reads them through a local, gitignored `CLAUDE.md` that imports this file.)

## Commands
- `npm test` — Vitest suite
- `npm run lint` — ESLint; keep it at 0 problems (CI does not run it, so check before every PR)
- `npm run type-check` — TypeScript
- `npm run build` — production build (needs `DATABASE_URL`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL` set, any values)
- Runtime is Node.js 24 (Docker image `node:24-alpine`, CI `node-version: '24'`)

## Project Overview
Web-based event management and visitor planning system for the Higher Education Information Day (HIT) at ZSB Osnabrueck. HIT date: **November 19, 2026**.

## Tech Stack
- **Framework:** Next.js 16 App Router, React 19, TypeScript
- **Database:** PostgreSQL with Prisma 7 ORM
- **Auth:** NextAuth v5 (role-based: ADMIN, ORGANIZER, PUBLIC)
- **Styling:** Tailwind CSS + shadcn/ui
- **Maps:** Leaflet
- **AI/LLM:** any OpenAI-compatible gateway (e.g. LiteLLM, vLLM); the Gemini path was removed
- **Testing:** Vitest + React Testing Library
- **Language:** All UI text in German

## Key Decisions
- **Homepage hero banner is toggleable:** Two implementations live side-by-side. Default is the static PNG (`public/infotag-banner.png`) rendered via Next.js `<Image>`. Setting `NEXT_PUBLIC_ANIMATED_BANNER="true"` swaps in the animated SVG banner (`AnimatedHeroBanner` in `src/components/home/animated-hero-banner.tsx`, CSS module alongside, source SVG at `public/banner/elemente_benannt.svg`). Only the background layer swaps — the dark `bg-black/30` overlay, the Störer, and the existing Badge/H1/CTA/stats overlay stay on top in both modes. The animated banner uses `preserveAspectRatio="xMidYMid slice"` on landscape and switches to `meet` on portrait/narrow viewports (via a `matchMedia('(max-aspect-ratio: 1/1)')` listener) so all 17 kept SVG elements stay visible on phones; it also respects `prefers-reduced-motion`. The KEEP config (per-element position, scale, animation, duration) lives at the top of the component and is the single place to tune which graphic elements survive and where they land. **Build-time only:** `NEXT_PUBLIC_*` is inlined at `npm run build`, so the Dockerfile (`ARG`/`ENV NEXT_PUBLIC_ANIMATED_BANNER`) and `.github/workflows/docker-publish.yml` (`build-args:`) must pass it through; setting it on the runtime container has no effect.
- **Footer contact email is runtime-configurable:** `Footer.tsx` reads `process.env.CONTACT_EMAIL` (no `NEXT_PUBLIC_` prefix) with fallback `'hit@zsb-os.de'`. Footer is a server component (resolved by removing an accidental `'use client'` from `src/app/(public)/layout.tsx`), so the value is read at request time — a deploy-time change to `.env` + container restart is enough, no image rebuild needed. Do NOT switch this back to a `NEXT_PUBLIC_*` var: that would bake the address into the client bundle and re-introduce the previous build-time-vs-runtime divergence. Keep `EMAIL_TO` (server-only, used by `src/lib/email.ts` for SMTP delivery) separate from `CONTACT_EMAIL` (server-only, displayed in the footer) — they are different addresses with different lifecycles.
- **"Start" in the header leaves the app:** the HIT site is embedded in the ZSB website, so the "Start" menu entry (desktop and mobile) points to `START_URL` (server-only, request-time, default `https://www.zsb-os.de/hit`), read in `MainLayout` and passed to `Header` as `startHref`. Rendered as a plain `<a>`, not `next/link`. The internal homepage `/` still exists (logo/footer/direct links) — do not remove it.
- **Public layout must stay a server component, and it renders per request:** `src/app/(public)/layout.tsx` is intentionally NOT marked `'use client'`. That keeps `MainLayout` → `Footer` in the server tree so `Footer` can read non-public env vars. `MainLayout` also `await connection()`s before reading `START_URL`; without it Next prerendered every public page without dynamic APIs (`/events`, `/schedule`, `/route-planner`, `/hilfe`, `/impressum`, …) at build time, which froze `START_URL` and `CONTACT_EMAIL` to the build's values on those pages while `/home` showed the runtime ones (fixed in v0.18.0). All public routes are therefore `ƒ` (dynamic) in the build output; the per-request render cost is a few ms. Don't remove the `connection()` call or add `export const dynamic = 'force-static'` under `(public)`. Header is `'use client'` and that is fine — server components can render client components as children. If you find yourself needing `'use client'` at the layout level, push the client logic into a child component instead.
- **Mobile-first design** — students primarily use phones
- **Corporate colors:** Uni = `#AC0634` (burgundy), HS = `#009EE3` (cyan blue)
- **Footer legal pages:** Local pages, copy from ZSB (Impressum/Datenschutz), update Datenschutz at project end
- **Study program links:** Clicking a Studiengang opens the internal `/events/program/[id]` route (events filtered by that program), mirroring the `/events/cluster/[id]` pattern. The program's external Uni/HS website is reachable via a separate ExternalLink icon next to the name on `/study-programs` and a "Zur Studiengang-Seite" link in the program-events page header. There is no internal Studiengang *detail* page — the external Uni/HS site remains the canonical detail page. **As of v0.13.0** each Studiengang carries **multiple labelled external links** (`StudyProgramLink` table: `label`/`url`/`sortOrder`; the former single `StudyProgram.url` was migrated in and dropped). All public renders (study-programs list, event detail, program/cluster pages) show every link.
- **Events landing is entry-points only:** `/events` does NOT render an event list. It renders a search bar, two cluster tile sections (Studienfelder Universität / Hochschule), and 5 link rows in this exact order: Lehramt, Studiengänge A-Z, Infomärkte, Rund ums Studium, Multiplikator\*innen-Café. Clicking a Studienfeld tile opens `/events/cluster/[id]`, which renders the **programs grid for that Studienfeld** (mirroring the old zsb-os.de pattern) with a CTA "Alle Veranstaltungen dieses Studienfelds anzeigen" linking to `/events/cluster/[id]/all` for the full event list via `<EventListView staticFilters={{ clusterId: id }}/>`. The other 4 link rows open sub-routes that render events directly via `<EventListView>` with a `staticFilters` prop that ends up as query params on `/api/events/public`.
- **"Rund ums Studium" labelling:** Visitor-facing label for events with `isCrossProgram=true`. Replaces the older "Studiengangsübergreifend" / "Hochschulübergreifende Angebote" wording. The Prisma field name `isCrossProgram` is unchanged — only the German display label changed. The admin Excel/CSV export column header keeps the old "Studiengangsübergreifend" label (admin-internal, intentional).
- **Cluster taxonomy is institution-scoped:** `StudyProgramCluster` has `institution Institution` (UNI / HOCHSCHULE / BOTH). Reads typically filter by institution to render the two separate sections. `BOTH` is in the enum but no seeded cluster uses it; treat `BOTH` as a future-proofing edge case, not a normal value. Cluster icons were removed site-wide — do not reintroduce icon rendering on `study-programs`, `EventFilters`, exports, or the cluster sub-view header without explicit user request.
- **Multiplikator\*innen-Café configuration:** `HitEdition.multiplikatorCafeEventId` (nullable FK to `Event` with `ON DELETE SET NULL`). Configured via the admin editions page. The public landing link is hidden when the FK is null. Always use the asterisk in the visible label (`Multiplikator*innen-Café`), never a colon.
- **Travel-time warnings (route-planner + schedule timeline):** Two paths share the same intent.
  - Server: `analyzeTravelTimes` in `src/services/route-service.ts`. **Pre-filters events to those with resolvable coordinates, then iterates consecutive pairs of the filtered list** — never iterate raw `events.length-1`. The route-leg coloring matches analyses to legs by `(eventFromId, eventToId)` pair, not by index, because both arrays may shrink at different rates.
  - Client: `useScheduleTravelWarnings` (`src/hooks/use-schedule-travel-warnings.ts`) calling pure helper `detectTravelWarnings` (`src/lib/schedule-travel.ts`). Skips Infostände on either side, same-building pairs, overlapping events, and pairs missing the cached route.
  - The default buffer on top of raw walking time is 5 minutes.
- **Schedule context self-heals stale `building.slug`:** Older schedule items in localStorage have `slug=''` because of a previous `EventCard` reshape bug. After `LOAD_SCHEDULE`, the context detects items with empty slug, refetches them via `/api/events/public/[id]`, and dispatches `PATCH_EVENTS`. New items added after the fix have correct slugs from the start.
- **Header logo:** Two halves of the official ZSB combined logo (`public/logos/uos-half.svg`, `hs-half.svg`), each in its own external `<a>`. The footer no longer carries any logo at all — the header is enough; the footer "Institutionen" column shows only the three text links (Universität, Hochschule, ZSB). (`uos-hs-combined.svg` still exists in `public/logos/` but is no longer rendered.)
- **Schedule priority is a 3-level enum:** `SchedulePriority = 'HIGH' | 'MEDIUM' | 'LOW'` (German labels Hoch / Mittel / Niedrig) defined in `src/types/schedule.ts`. Lives in localStorage only — DB `ScheduleItem.priority` is currently unused by code. Default is `MEDIUM`. The badge in the list view appears only when the value differs from the default. **As of v0.13.0** every timeline card shows a compact priority badge in its header that cycles Hoch→Mittel→Niedrig on click (replacing the old height-gated 3-button control); the full radiogroup stays in the list view. Older localStorage entries that stored a number are normalized on load (1 → HIGH, 2 → MEDIUM, 3+ → LOW) via `normalizeStoredPriority` in `src/contexts/schedule-context.tsx`.
- **Timeline cards must respect their time slot:** `ScheduleTimeline.tsx` uses fixed `height` (NOT `min-height`) and `overflow-hidden`. A 45-min Vortrag with a long title in a narrow conflict column wraps to 5+ lines; if we let cards grow with content, they visually claim time slots they don't own (e.g. 11:00–11:45 cards appearing to extend until 13:00). Title uses `line-clamp-3`, building name uses `truncate`, and both have `title=""` tooltips so hover reveals the full text. The "see everything" path is the title link to `/events/[id]` plus a card-level `title` tooltip (full title/time/location on hover). (The former `height >= 144` gate that hid priority controls on short cards was removed in v0.13.0 — priority is now a single compact click-cycling badge in the card header, which fits all card heights.)
- **Schedule sidebar date selector hides for single-day editions:** When `scheduleDates.length <= 1` (the typical HIT-on-one-day case), the entire "Datum auswählen" sidebar card is suppressed in `src/app/(public)/schedule/page.tsx`. The date is still shown as the section heading above the timeline, and the Übersicht stats card (always rendered) covers per-day counts.
- **Studiennavigator recommendations come from the model, not from code:** `src/lib/navigator-prompt.ts` renders every `StudyProgram` (name, institution, Studienfeld, Lehramt tags) into the system prompt with short IDs `P1..Pn` (stable order: institution rank, then `compareDe`). The model ends each reply with one trailer line — `OPTIONS: [...]` while asking (4–5 questions, fixed RIASEC first question served from code) or `EMPFEHLUNG: {"programs":[{"id","reason"}],"summary"}` when recommending — parsed by the pure `parseNavigatorReply` in `src/lib/navigator-reply.ts`. The service resolves short IDs to cuids, drops unknown IDs, stores the pick on the session and attaches PUBLISHED events of the active edition. There is **no keyword matcher and no offline fallback**: gateway failure → `NavigatorUnavailableError` → HTTP 503 → German "nicht erreichbar" message in the chat. Only OpenAI-compatible gateways are supported (`OPENAI_API_BASE_URL` / `OPENAI_API_KEY` / `OPENAI_MODEL`); the Gemini path was removed. Sessions are stored in Redis (`navigator:session:<id>`, 2 h TTL) via `src/lib/navigator-session-store.ts` with an in-memory fallback. `processMessage` serialises concurrent turns per session via an in-flight promise map (per-process lock, sufficient for the single-container deployment) and works on a `structuredClone` of the stored session so a failed turn leaves no trace. `ProgramRecommendation.isLehramt` is computed server-side and set **only** for Lehramtsstudiengang / Berufliche Fachrichtung rows (`isLehramtStudiengang || isBeruflicheFachrichtung`) — a non-empty `lehramtTypen` alone (a Fach merely tagged for a Schulform) does NOT trigger it; it drives the "Kombinationsregeln" link — do not reintroduce name-substring Lehramt detection in the UI. Don't reintroduce name-substring scoring or a per-turn "messageCount >= 4" recommendation trigger in the UI — recommendations appear exactly when the model emits them. `/api/navigator` is rate-limited per IP via `src/lib/rate-limit.ts` (POST 20/min, GET 10/min); client-supplied session IDs (POST body `sessionId`, GET/DELETE `sessionId` query param) are format-validated against `NAVIGATOR_SESSION_ID_RE` (exported from `navigator-service.ts`) before use — an invalid POST id silently mints a fresh session, an invalid GET/DELETE id returns 400.
- **Campus values are normalised at the API boundary, and building coordinates are nullable:** the DB stores free-text campus names ("Innenstadt", "Schloss", "Westerberg", "Caprivi"); `toBuildingInfo` in `route-service.ts` maps them through `normalizeCampus()` (`src/lib/campus.ts`) to the `CampusKey` union (`schloss` | `westerberg` | `caprivi` | `other`, with `CAMPUS_LABELS` / `getCampusColor`). Never compare raw `building.campus` strings in the UI. `BuildingInfo.coordinates` is `Coordinates | null` — never 0/0 — and all centre/bounds maths goes through `src/lib/map-center.ts` (`computeMapCenter`, `buildingsWithCoordinates`); the routing APIs return 422 for buildings without a position. `CampusMap` re-fits its viewport via `MapViewportSync` (react-leaflet `useMap`) whenever the `viewportKey` prop changes, because `MapContainer` only reads `center`/`zoom` on mount. The Zeichen-224 bus-stop icon is a round sign and is anchored at its centre. Booklet cluster sections are keyed by `institution::name` so the two "Zentrale Angebote" clusters stay separate.
- **NavigatorChat restart needs the init ref reset:** the session is initialized inside an effect keyed on `sessionId`. `initializingRef.current` must be reset to `false` in its `finally` block, otherwise the next run early-returns and Neu-starten leaves the chat empty. `handleRestart` MUST NOT start a session itself — it only clears `sessionId` (setting `isLoading` first when there was a session), which re-runs the effect.
- **Email relay:** `relay.rz.uni-osnabrueck.de` port 25, no auth needed (Uninetz only)
- **Email notifications:** Full event details in email, trigger on both new submissions and edits (to hit@zsb-os.de)
- **Routing API:** Google Maps Directions API (included in university cloud contract)
- **The route cache is only valid for the coordinates it was computed from:** every read/write of `cached_routes` goes through `getWalkingRoute` (`src/services/route-cache.ts`), used by `getDirections`, `/api/routes/directions` and `/api/routes/seed`. A row also stores `from/toLatitude/Longitude`; it is served only while they equal the buildings' current coordinates, otherwise it is recomputed (rows with NULL positions, i.e. older than v0.19.1, count as stale). Before this, the cache was keyed by slug alone: routes computed while building 11 (Schloss) had coordinates at Westerberg kept leading visitors from CN/SL/Physik to building 69 after the position was corrected. Don't add another direct `prisma.cachedRoute` access.
- **`findBuilding` tries the exact slug first:** admins pick slugs freely ("CN", "AVZ", "Fachbereich Biologie"); the lookup used to lowercase before the exact match, so mixed-case slugs depended on a name substring fallback (which could pick the wrong building) and "Fachbereich Biologie" was not found at all (routes to building 35 answered 404). Order is now: exact slug → slug in other case → name contains / short name equals.
- **Analytics:** the university's Matomo instance (tenant provided by the RZ)
- **No social login:** Anonymous profiles only, shared via QR/short link (avoids Datenschutz issues)
- **Event times are Berlin wall-clock:** DB columns are `timestamp without time zone` holding Berlin values, and JS Dates carry those values in their UTC components. Always format event timestamps via `src/lib/event-time.ts` helpers (`formatEventTime`, `formatEventDateLong`, `isSameEventDay`, etc.) — never `date-fns format()`, `toLocaleTimeString()`, or local `getHours()/getMinutes()` on event timestamps. The `EventForm` save path appends `Z` to the typed time so writes interpret it as Berlin wall-clock too. Real-time data (bus positions, chat messages) keeps user-local formatting.
- **Conflict detection is centralized:** All schedule conflict checks go through `src/lib/schedule-conflicts.ts` (`eventPairOverlapMinutes`, `detectConflicts`). Both the client `ScheduleContext` and server `recommendation-service` delegate to it. Infostände never participate in conflicts (all-day walk-in events). Do not re-implement overlap math or Infostand-skip logic elsewhere — a previous regression was caused exactly by that duplication.
- **Multi-year editions:** Every `Event`, `UserSchedule`, and `SharedSchedule` is scoped by `editionId` (see `HitEdition` model). Exactly one edition is `ACTIVE` at a time; reads default to the active edition via `src/lib/active-edition.ts::getActiveEdition()`. Rollover (`edition-service.rollover`) creates a new ACTIVE edition and deep-clones events as `DRAFT_FROM_ROLLOVER` for review in the admin Prüfstand (`/admin/pruefstand`). All public/export/recommendation paths filter by `reviewStatus = 'PUBLISHED'` to prevent draft leakage. Past-edition `SharedSchedule` short-links (`/s/<code>`) resolve cross-edition and render read-only on the schedule page. **Rollover (v0.13.0):** the modal accepts any **unique** year (no longer forward-only), so a lower test year is allowed; the migration was verified end-to-end. Event date for all events comes from the edition (see below).
- **Melder fields (v0.13.0):** `Melder` has **no** `fakultaet`/`fachbereich` — a single `organisationseinheit` (relabelled per affiliation via `organisationseinheitLabel` in `src/lib/validations/melder.ts`: Fakultät@HOCHSCHULE, Fachbereich@UNI, Institution@BEIDE/EXTERN) plus `adresse` (shown instead of `room` only for EXTERN). Conditional fields render in `MelderSection.tsx` and `/admin/melders`; fields appear only after an affiliation is chosen.
- **Event date is central (v0.13.0):** `EventForm` has no date picker — the date always comes from `getActiveEdition().hitDate` (read-only display). Don't reintroduce a per-event date input. New events also have **no default institution** (must be chosen; schema message "Bitte Institution auswählen").
- **Hochschulübergreifend = `institution: BOTH` = external (v0.13.0):** `event-service` forces `isCrossProgram=true` on create+update when institution is BOTH; the public API (`/api/events/public`) matches institution **exactly** so BOTH is excluded from UNI/HS lists and surfaces under Rund ums Studium; the badge is greyed; the form auto-checks+disables "Rund ums Studium". Existing rows backfilled by migration `both_events_cross_program`.
- **Merkliste vs Stundenplan (v0.13.0):** two localStorage collections in `ScheduleProvider` (`hit-schedule` + `hit-watchlist`), **mutually exclusive** (adding to one removes from the other; promote = move). Buttons: `WatchlistButton` ("Merken"/"Gemerkt") and `AddToScheduleButton` ("In den Stundenplan"/"Im Stundenplan"). Merkliste page at `/merkliste`.
- **EventType label/colour maps are duplicated** across ~16 files (event form, cards, schedule, calendar, recommendations, exports, emails). Adding a type means editing them all — watch the strongly-typed `Record<EventType,string>` maps in `export/html` + `export-service` (the PDF booklet reuses `formatEventType` from `export-service`), and the legacy `EVENT_TYPE_LABELS` in `admin/events/new` + `email-templates` (extra/duplicate keys). A future cleanup could centralise these.
- **`buildings` PK constraint** was renamed `Building_pkey`→`buildings_pkey` (migration `normalize_building_pkey`) to clear long-standing Prisma drift — prod still has the old name, so the rename runs there on deploy.
- **German sorting is app-level, not DB-level:** the container runs `postgres:16-alpine` (musl, `C` collation), so `ORDER BY name` puts Ö after Z. All user-visible alphabetical ordering goes through `src/lib/sort-de.ts` (`compareDe`, `compareDeBy`, `azLetter`); Prisma `orderBy` is kept only for determinism and re-sorted in the service. `azLetter` folds Ä/Ö/Ü/ß onto A/O/U/S so A-Z indexes have no umlaut sections.
- **Excel worksheet names must go through `uniqueSheetName`:** ExcelJS throws on duplicates and Excel truncates at 31 characters, which is how the by-Studiengang export used to 500 with 200+ programmes. Never call `addWorksheet` with a raw name.
- **Editable homepage texts:** `ContentText` stores **overrides only**; shipped defaults live in `src/lib/content-slots.ts`, so an empty table renders correctly. Read via `getContentTexts()` in server components. Adding a slot = registry entry + read it in the page; the `/admin/texte` editor is generated from the registry. The homepage is a **server component** because of this — do not reintroduce `'use client'` there.
- **Melder picker is ADMIN-only:** `/api/melder/options` enforces the role server-side. Organizers are external submitters and must not browse all Melder contact data. `MelderSection`'s read-only latch comes from `EventForm`'s mount-time `isMelderReadOnly` — one source of truth, because the persist guard depends on it.
- **Event deletion mirrors update authorization:** ADMIN unrestricted; ORGANIZER only their own event before the deadline. The admin UI must surface the API's error message — a silently swallowed non-ok response is what made deletion look absent.
- **`/api/melder/options` returns 403, not 401, for unauthenticated callers:** this matches its sibling `/api/melder/all`, whereas `/api/melder`, `/api/melder/[id]` and `/api/melder/upsert` return 401. The split is intentional and pinned by a test — don't "fix" it to 401 and break the suite.
- **`getActiveEdition()` throws when no edition is ACTIVE** — it does not return null. Every caller must handle the throw explicitly; the homepage guards it with catch-log-degrade so a misconfigured deployment still renders. Do not simplify that guard away.
- **Sorting an `Institution` value must use an explicit rank map** (UNI, HOCHSCHULE, BOTH — the Postgres enum declaration order), never `localeCompare` on the enum's string value, which would reorder the institution groups.
- **`MelderSection`'s `userInteractedRef` gates the own-profile auto-fill** so that a fresh pick or reset is not silently reverted once the in-flight own-profile fetch resolves. Do not remove it.
- **Lehramt Binnendifferenzierung (June 2026, multi-Schulform):** `StudyProgram.lehramtTypen` (`LehramtTyp[]` — a single Unterrichtsfach is tagged with **several Schulformen at once**; empty = not Lehramt) + `isLehramtStudiengang` (the one dedicated Lehramt-Studiengang per Schulform, not a Fach; its events show first) + `isBeruflicheFachrichtung`. The earlier single `lehramtTyp` enum and the `StudyProgramUnterrichtsfach` self-relation were **removed** (migration `lehramt_multi_schulform` backfills the array and drops both). Shared labels/validation/grouping in `src/lib/lehramt.ts` (`normalizeLehramtInput` enforces: Fachrichtung needs BERUFSBILDEND; a Lehramt-Studiengang can't also be a Fachrichtung; `groupLehramtPrograms` returns per-Schulform `{lehramtStudiengang, faecher}` and `{lehramtStudiengang, fachrichtungen, allgemeinbildend}` for Berufsschule). Admin classifies via multi-select Schulformen + the two checkboxes in the study-programs dialog. `/events/lehramt` is a server page (`getLehramtPageData` in `src/services/lehramt-service.ts`): per Schulform the Lehramt-Studiengang events inline first (via `LehramtEventsSection` `studyProgramId`), then Fächer/Fachrichtungen as clickable lists → `/events/program/[id]` (normal display). The Berufsschule section (`id="berufsbildend"`) lists Berufliche Fachrichtungen then Allgemeinbildende Unterrichtsfächer (one font size smaller) with a mandatory-combination warning. The two Lehramt Studienfeld tiles on `/events` route to `/events/lehramt` (Uni) and `/events/lehramt#berufsbildend` (HS) by cluster name. Public API filters: `lehramtCombined` = `lehramtTypen` non-empty; `lehramtTyp=X` = `lehramtTypen has X`; `excludeFachrichtungen` unchanged.

- **Studiennavigator on/off is a code constant:** `NAVIGATOR_ENABLED` in `src/lib/features.ts` (currently `false`, at the ZSB's request for HIT 2026 — re-review the recommendations with the subject representatives before turning it back on). It gates the header/mobile/footer links, the homepage CTA, the `/navigator` page (`navigator/layout.tsx` → `notFound()`), all `/api/navigator*` handlers (`navigatorDisabledResponse()` → 404, checked before rate limiting so the model is never called) and the manual's "Studiengangs-Navigator" section (`removeMarkdownSection`). Deliberately a code constant, not an env var: switching it back on should go through a review of the recommendations and a release.
- **Visitors have no link to `/hilfe`:** the pages still exist (admin sidebar "Hilfe" → `/hilfe/admin`, index links to all three manuals), but nothing on the public site points there. Don't reintroduce a public help link or `HelpLink` icons without a ZSB request.
- **Coordinates are typed into text inputs, never `type="number"`:** admin coordinate fields go through `src/components/admin/CoordinateInputs.tsx` (text + `inputMode="decimal"`, "z.B." placeholders, German decimal comma, a pasted Google-Maps "lat, lng" pair is split across both fields, inline error, non-blocking "nicht in Osnabrück" warning). A number input's placeholder looked like a stored value that couldn't be selected, and its spinner/arrow keys turned an empty field into -1 / 1. Server side, every write goes through `validateCoordinatePair` (`src/lib/coordinates.ts`): both or neither, range-checked, 400 with a German message instead of storing NaN. Values are stored unrounded (6 decimals ≈ 0.1 m).
- **Shuttle stops live in the database:** `ShuttleStop` (`shuttle_stops`: name, latitude, longitude, optional `directionsNote`, `sortOrder`), managed by the `ShuttleStopsCard` on `/admin/shuttle-buses` via `/api/admin/shuttle-stops[/id]` (ADMIN, 401 otherwise — same as the shuttle-bus API). `/api/bus-positions` serves them as `stops`. The former hardcoded `SHUTTLE_STOPS` list and the unused `campus` field are gone; migration `shuttle_stops` carried the three stops over unchanged.

- **The PDF booklet has its own Lehramt section and lists the Infomarkt stands (v0.20.0):** `exportService.eventsForBooklet` feeds `/api/export/pdf/booklet`. The two Lehramt Studienfelder get no section (`isLehramtCluster` in `src/lib/lehramt.ts`, matched by name like the `/events` tiles); instead a Lehramt section after the Universität mirrors `/events/lehramt` (`groupLehramtEventsForBooklet`): per Schulform the events of its Lehramt-Studiengang, then per berufliche Fachrichtung. The overarching "Lehrer\*in werden" talks are `isCrossProgram`, so they must be matched by study programme, not by Studienfeld — that is how they went missing before. A non-cross event left without a Studienfeld lands in "Ohne Studienfeld" unless the Lehramt section shows it, so no event silently disappears. Infomärkte list their stands (`groupInfoMarketsForBooklet`) in the order of `/events/infomaerkte` (shared `compareInfoMarkets`, `src/lib/info-markets.ts`). TOC page numbers come from invisible markers collected **last write wins**: while splitting a page, react-pdf calls the render callbacks of everything not yet placed with the page being split, so a marker in the middle of a `Page` first reports too early a page. Wrap a mid-page heading and its marker in `keepWithNext` so they move to the next page together.
- **Event photos live in the database, not in `public/`:** `/api/upload/image` sniffs the type from the file's leading bytes (`detectImageType` in `src/lib/event-media.ts`; JPEG/PNG/WebP only, never trust the client MIME type — we serve the bytes back from our origin), stores them in `UploadedImage` (`uploaded_images`, `bytea`) and returns `/api/images/<id>`, which serves them with `immutable` caching. Do not go back to writing into `public/uploads/`: the production server only serves `public/` files that existed at build time (404 otherwise) and the app container has no volume, so every redeploy deleted them — that is why uploads "did not work" in the October 2026 round. Migration `event_media` cleared the dead `/uploads/...` references. `EventPhoto` hides itself when an image fails to load, so a bad external address never shows a broken frame to visitors.
- **`/_next/image` is a public image proxy, so Next.js and sharp must stay patched:** `next.config.js` allows `remotePatterns` for any HTTPS host because photo addresses are pasted from arbitrary sites, which means anyone (no login) can make the server fetch and decode an image. The critical optimizer RCE GHSA-2xp9-vwfh-vxw4 was reachable this way until v0.19.3. `dangerouslyAllowLocalIP` must stay off, and `maximumDiskCacheSize` caps the cache at 500 MB because the server disk is 10 GB. Don't "fix" this by rendering external photos `unoptimized`: visitors' browsers would then contact the third-party hosts directly (Datenschutz).
- **Event videos are YouTube/Vimeo links, embedded click-to-load:** `Event.videoUrl` holds the canonical watch URL produced by `parseVideoUrl` (`src/lib/video-embed.ts`). `EventVideo` renders a placeholder with a privacy notice and loads the youtube-nocookie / Vimeo `dnt=1` player only after "Video abspielen"; no thumbnail is fetched from the provider (that would already transfer data). The Datenschutz page has a matching section. Don't embed the iframe on page load.
- **`EventForm` does not run its zod schema on submit:** it submits `form.getValues()` (no `handleSubmit`), so `eventFormSchema` is effectively types only. Field rules that must hold are enforced in the component (e.g. `VideoLinkInput`, the submit guard for an unusable video link) and on the server (`validateEventMedia` in POST `/api/events` and PUT `/api/events/[id]`, German 400 messages). Likewise the form's `''` placeholders reach the service unchanged: `event-service` stores a lecturer's `affiliation: ''` as `NULL` (create, update, duplicate) — the Affiliation enum rejects `''`, which made every event with a lecturer lacking an affiliation unsaveable from the edit page (v0.19.2).
- **Effects must not set state synchronously (`react-hooks/set-state-in-effect`, enforced since eslint-config-next 16.4):** the rule flags an effect that calls any component-scope function containing `setState`, even when the state is only set after an `await`. The patterns used throughout the code: (1) loaders set state only in promise callbacks (`fetch(...).then(...).catch(...).finally(() => setLoading(false))`), the effect calls the loader, `loading` starts as `true`, and a separate `fetchX()` wrapper (`setLoading(true)` + loader) is what event handlers call to reload; (2) lists whose filters re-trigger the fetch build their query string during render and set `loading` there when it changes ("adjusting state while rendering", e.g. `requestedQuery` in `EventListView`); (3) derive values instead of storing them (`isLoadingShared` on the Stundenplan). Don't silence the rule with an `eslint-disable`. The two deliberate suppressions are the sign-out full reloads (`window.location.href = '/'` drops all client state of the session) and one `watch()` in `EventForm` (`react-hooks/incompatible-library` only matters with React Compiler, which is not enabled).
- **Responsive grids need an explicit base column:** write `grid grid-cols-1 lg:grid-cols-3`, never `grid lg:grid-cols-3` alone. Without explicit columns the phone layout's single track sizes to its content, so one long `truncate`d event title made `/route-planner` about 1500px wide on phones and pushed its buttons off screen (v0.19.4). Rows that put a heading and a button side by side need `flex-wrap`. Check new pages at 390px: `document.documentElement.scrollWidth` must equal the viewport width.
